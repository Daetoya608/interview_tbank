# Опыт Амаля

## Профиль

Амаль Атамурадов, четвёртый курс ФПМИ МФТИ. Основной профиль — Python backend. Python изучает со школы; с конца школы занимался заказной разработкой через знакомых. В 2026 году прошёл стажировки в Яндексе и Т-Банке. Развивает собственный проект LegacyDoc.

## Яндекс

**Система:** внутренняя платформа A/B-экспериментов. Уточнение Амаля: работа велась над бэкендом админки платформы.

**Стек:** Python, Django, DRF, PostgreSQL; в задачах использовались YT и MCP.

**Основная история:** спроектировал и реализовал этап подготовки ресурсов для ML-экспериментов, настроил синхронизацию конфигураций из репозитория в динамические таблицы YT, интеграции со смежными сервисами и сквозные тесты, довёл изменение до продакшена.

**Другие задачи:** самообновляемые уведомления в Трекере, фильтры поиска, оптимизация запросов, MCP-сервер для создания экспериментов через AI-агента.

**Что важно объяснить:** сценарий в админке; границы личного проектирования; вход и выход этапа; запуск и завершение; обработка частичного сбоя; проверка результата.

Не уточнено, использовалась ли собственная админка или расширение стандартного Django Admin. До уточнения в рассказе используется нейтральная формулировка «бэкенд админки на Django и DRF».

## Т Банк

**Команда:** Rosetta, платформа распознавания документов. Работа началась в августе 2026 года; стажировка завершилась. В текущей команде нет штатной позиции для продолжения.

**Задачи шлюза:** API к ML/VLM-моделям, валидация входных данных, лимиты, JWT/JWKS и scopes через T-Work/ID-Hub, rate limiter на Valkey, circuit breaker с изоляцией по моделям.

**Общие компоненты:** Python-библиотеки для Kafka, HTTP-клиента, observability и длительных задач; сервисный шаблон и тестирование.

**Эксплуатация:** подготовка сервисов к передаче SRE, инструкции по сбоям и восстановлению, описание устройства и зависимостей, мониторинг, бизнес-дашборды и контракты данных для аналитики.

**Обсуждавшийся стек:** Python, FastAPI, asyncio, Kafka, OpenTelemetry, Prometheus, Grafana, Docker, GitLab CI, pytest.

Формулировки описывают участие в компонентах системы. Они не означают, что Амаль единолично спроектировал и написал всю платформу или весь шлюз с нуля.

## Дополнительный опыт

- Летняя школа Яндекса: серверная часть сервиса для промоутеров, FastAPI, SQLAlchemy, S3, REST API и авторизация, командная работа с наставниками.
- Мессенджер: сервер на FastAPI, клиент на PyQt, PostgreSQL и локальный SQLite-кэш, асинхронное взаимодействие и WebSocket.
- LegacyDoc: собственный проект анализа кодовой базы, графа зависимостей и документации. Развивается в сторону платформы агентных сценариев. Архитектура, организация разработки и выбор продуктовых приоритетов.

## Как описывать вклад

Для каждой задачи разделять:

1. Что уже было в системе.
2. Какую цель поставили.
3. Какие решения принимал Амаль.
4. Что обсуждалось с наставником или командой.
5. Какие изменения реализовал лично.
6. Как проверялось и внедрялось решение.

Не использовать вымышленные показатели нагрузки, экономии времени, покрытия или ускорения. Если измерение не сохранилось, описать проверяемое изменение поведения.
