# Вакансия и связь с опытом

## Что известно о позиции

Команда создаёт внутреннюю платформу управления и настройки партнёров. Вакансия описывает админ-панель, которая обеспечивает интеграцию с внутренними сервисами банка и внешними партнёрами.

Обязанности: разработка функциональности, улучшение и рефакторинг кода, взаимодействие с заказчиками и командами разработки и тестирования, оценка и планирование задач, unit-тесты и code review.

Требования на скриншоте:

- Python, Django, pytest, asyncio.
- SQL, индексы, транзакции, Django ORM и SQLAlchemy.
- CI/CD, Docker, Kubernetes.
- RabbitMQ или Kafka — дополнительный плюс.

Грейд, конкретная версия Django, нагрузки и формат собеседования в предоставленном описании не указаны.

## Контекст платформы

В более широком описании PIP — централизованная система исходящих синхронных интеграций с API партнёров. PIP-Gateway обрабатывает запросы; PIP Admin управляет конфигурациями. Среди функций платформы названы доступы, маршрутизация, преобразование данных, кэширование и защита персональных данных.

Синхронный запрос-ответ на уровне интеграции совместим с асинхронной реализацией Python: вызывающий клиент ждёт ответ, а сервер может конкурентно обслуживать другие запросы.

## Соответствие опыту

| Требование команды | Релевантный опыт | Акцент на интервью |
| --- | --- | --- |
| Админка и Django | Бэкенд админки платформы A/B-экспериментов в Яндексе | Пользовательский сценарий, API, ORM и тесты |
| Конфигурации и интеграции | Препроцессинг, синхронизация с YT, смежные сервисы | Источник данных, запуск, статус и сбои |
| SQL и оптимизация | PostgreSQL, фильтры поиска и оптимизация запросов | Один настоящий пример с диагностикой |
| Асинхронность и API | Шлюз к ML/VLM в Т-Банке | Ожидание зависимостей, пулы, таймауты |
| Права и надёжность | JWT/JWKS, scopes, Valkey, circuit breaker | Механизм, ограничения и отказные сценарии |
| Тестирование | e2e, тесты библиотек и сервисов | Что проверяется и какие ошибки обнаруживаются |
| Эксплуатация | Мониторинг, инструкции по сбоям, подготовка к SRE | Как понять причину проблемы и восстановиться |
| Работа в команде | Стажировки и LegacyDoc | Личная ответственность и согласование изменений |

Практическую глубину Kubernetes нужно оценить отдельно. Название технологии в требованиях не доказывает, что ожидается самостоятельное администрирование кластера.

## Порядок подготовки

1. Свои задачи на Django и SQL.
2. Тестирование, рефакторинг, ревью и взаимодействие.
3. Asyncio, HTTP и поведение зависимостей.
4. CI/CD, Docker, основные сущности Kubernetes.
5. Брокеры и общая архитектура шлюза.

В самопрезентации сначала полезно рассказать об админке в Яндексе, затем о шлюзе и эксплуатации в Т-Банке.
